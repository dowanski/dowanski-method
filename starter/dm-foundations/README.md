# DM Foundations — Inactive Receiver Library

Status: Inactive until an accepted QDI-to-DM handoff authorizes DM setup

## Why this directory exists

QDI discovers what the project is, what matters, what could fail, and what the
human accepts. This library receives that accepted understanding and provides
one proportional documentation foundation:

| Foundation | Use when | Active-base character |
|---|---|---|
| Light | One coherent, low-consequence, reversible outcome | Combined project truth plus one direct Work Packet |
| Standard | Work is expected to grow across stages, decisions, or contributors | Separate current truth, plan, decisions, debt, and one direct Work Packet |
| Governed | A hard trigger or material consequence requires explicit controls | Full routed Main Set with earned control and review records |

Documentation Weight is not a quality grade. The handoff must explain why the
next lighter foundation is insufficient and why more structure is unnecessary.
A Governed hard trigger cannot be canceled by a score or preference for fewer
files.

## Entry conditions

Do not continue unless all are true:

1. QDI Current State is `APPROVED_FOR_HANDOFF`.
2. The Pre-Build Blueprint and Context Cleanup result are accepted.
3. The human separately authorized handoff generation.
4. The completed handoff passed its verification list.
5. The handoff Owner Decision accepts DM setup and names one weight, one exact
   destination, and the documentation paths allowed to change.

If any condition is absent, return to the named QDI gate and stop.

## Receiver sequence

1. Read `CHOOSING_A_FOUNDATION.md`.
2. Confirm the selected weight against the accepted handoff.
3. Read `ADAPTING_A_FOUNDATION.md`.
4. Inspect only `light/`, `standard/`, or `governed/`—never all three.
5. Copy only the selected active base into the approved destination.
6. Adapt it from the handoff's accepted truth; do not copy the full discovery
   history into active documentation.
7. Add optional records only when the handoff names the condition that earned
   them.
8. Present the adapted route and first proposed Work Packet for human review.
9. Stop before implementation.

## What remains outside the active project route

- both unselected foundations;
- examples after orientation;
- optional templates that were not earned;
- raw QDI interview history;
- closed branches, sidequests, and retries;
- private or oversized evidence;
- proposed future workstreams;
- anything requiring authority the human did not grant.

An accepted documentation setup does not authorize implementation, commit,
push, publication, deployment, provider mutation, purchase, deletion, external
communication, or access to accounts or data.
