# Adapting a Foundation

Do not drop an entire folder into a repository and ask an agent to make it fit.
Install the smallest active base, replace starter context with observed truth,
and let the project earn additional structure.

## Human sequence

1. Confirm the selected Documentation Weight.
2. Copy its active base and keep `_examples/` and `_optional/` outside the
   active route.
3. Preserve the foundation AGENTS file's Continuing controls. Complete the
   project purpose, intended outcome, current state, scope,
   authority, evidence, owner gate, and stop conditions.
4. Turn unresolved facts into named questions with an owner and resolution
   gate. Do not guess.
5. Approve one active route and one eligible or explicitly blocked Work Packet.
6. Remove unearned prompts, examples, optional records, and future structures.

## Suggested first agent instruction

> Read the repository orientation, agent instructions, and documentation
> router. Inspect the current project without changing files. Identify which
> starter assumptions are accurate, which need owner answers, whether the
> selected Documentation Weight is sufficient, and which optional records—if
> any—the project has earned. Do not create new structures or implement work
> until the owner approves the adapted project set and first Work Packet.

## Evidence discipline

Name what each check proves, where and when it ran, who or what observed it, and
what it does not prove. A local screenshot is not live verification. A passing
test is not owner acceptance. A preserved branch is not a released product.

## Closure

After the review gate:

1. record the disposition and matched evidence;
2. return current capability, durable decisions, surviving debt, and the next
   legal entry to the parent;
3. freeze the accepted packet;
4. remove closed work from active routing and preserve it through sufficient
   version history or an earned archive;
5. create a successor only after its entry conditions and authority exist;
6. reconsider whether the current Documentation Weight is still necessary.

The foundation organizes work. It does not grant access, replace qualified
review, or make project decisions automatically.

## Resolve optional resources after installation

Keep the source kit outside the active project route. During adaptation, record
its exact location in the project router as an inactive resource reference.
At an earned optional-record trigger, read only the selected kit's optional
router and the named template, copy that record to its approved destination,
and update links for the installed location. This includes Governed owner
review and closeout records when their gates arrive.

A template path may describe its intended installed location. Validate that
location during adaptation; do not treat a missing template-relative path as
permission to search other projects or load all resources. If the source kit
has moved or is unavailable, report the exact missing source and obtain a
replacement before the dependent action. Resume the existing packet afterward.
